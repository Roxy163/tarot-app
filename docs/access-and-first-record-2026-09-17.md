# 访问门槛与首次日运记录改进

## 范围与边界

- 当前目标是功能、UI 和实际使用体验，暂不开发收费会员。
- 用户尚无自有域名或 ICP 备案；本轮已按要求用手机关闭 VPN 实测，并反馈“首页和登录都正常”。未提供具体网络类型，因此结论仅覆盖这次实测。
- 本轮完成现有架构内的免注册入口、断网记录、草稿保护与首次记录说明。
- 仍使用 Cloudflare Pages 与 Firebase；没有迁移账号、替换认证系统或改动数据库规则。
- 这次手机实测未发现必须使用 VPN 的门槛；不能外推到所有地区或运营商。模拟请求失败的测试用于验证降级体验。
- 改动已于 2026-09-18 随日常流程打磨统一发布，最终版本与线上验收见 `docs/daily-flow-polish-2026-09-18.md`。

## 已完成

1. 欢迎页明确说明无需注册、记录先保存在本机；记住首次进入，后续刷新直接进入应用。
2. 登录页顶部提供“先不登录，开始记录”。网络错误说明提供返回本机记录的路径，移除把 VPN 当作默认前提的说明。
3. 注册后的验证邮件发送与验证状态刷新加入等待上限；账号创建成功但邮件发送未确认时，保留账号并如实提示，不声称邮件一定已发送。
4. 首页解释当前浏览器的保存范围与备份；日运计数改为“日运归档”，同步面板计数明确为“本机手记 / 云端手记”。
5. 首次日运入口改为“写下第一直觉”，表单使用“记录日运 / 保存记录”，今日回看标为可晚些再填。
6. 日运草稿按账号和记录隔离，刷新或关闭后可重新打开续写。成功保存才清理草稿；注销账号时一并清理该账号草稿。
7. 本机写入失败时保留表单与文字并提示，不关闭表单或显示成功。手机输入使用 16px 字号，补齐记录弹窗的焦点管理和主要按钮 44px 触控面积。
8. 已登录日运先读取本机，再合并云端结果。等待期间不提前覆盖云端；合并使用最新内存记录，防止慢请求甚至同一 React 批次内的云端响应覆盖新抽的牌或新写的内容。

## 真实网络结论

用户于本轮反馈：手机关闭 VPN 后，当时线上地址的首页和已有邮箱账号登录均正常。当前不应以“必须开 VPN”为前提购买域名或迁移后台；若其他用户仍有失败，再收集具体网络和失败步骤。新 UI 后续于 2026-09-18 发布并完成独立游客浏览器验收；这不扩大原有手机网络样本的结论。
