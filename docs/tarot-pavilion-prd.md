## 1. 产品概述

### 1.1 产品名称

塔罗研习阁

### 1.2 产品定位

塔罗研习阁是一款面向塔罗学习者的个人研习工具，帮助用户完成日运记录、抽牌手记、典籍复盘、牌义注疏、牌义小考和公开案例浏览。

产品不以“一次性算命结果”为核心，而是围绕“记录 - 回看 - 复盘 - 沉淀 - 再练习”的长期学习闭环，帮助用户逐步建立自己的塔罗理解体系。

### 1.3 产品一句话

记录、注疏、布阵，构建你的个人塔罗手札。

### 1.4 目标用户

| 用户类型 | 典型需求 | 产品回应 |
| --- | --- | --- |
| 塔罗初学者 | 想记录每日抽牌和练习过程，但缺少系统方法 | 提供日运、手记、小考和牌义注疏 |
| 进阶学习者 | 想复盘历史案例，形成自己的牌义理解 | 提供典籍索引、筛选、导出和个人牌库 |
| 为他人占卜的用户 | 需要区分个人记录与客户记录，保留反馈 | 抽牌手记支持客户模式和客户反馈 |
| 手机端高频用户 | 想在日常场景里快速记录，不想流程太重 | PWA、移动端优先、日运快捷入口 |
| AI 辅助使用者 | 不知道如何给 AI 提供完整上下文 | 自动生成结构化解牌提示词 |

### 1.5 核心价值

1. 降低塔罗学习者的记录成本。
2. 让日运和普通手记可以被持续复盘。
3. 把分散的牌义理解沉淀为个人牌库。
4. 用轻量小考强化牌面、元素、行星、星座、宫位等记忆。
5. 在用户需要时提供 AI 解读提示词和关键词整理辅助。
6. 支持本地优先保存，登录后云端同步，降低记录丢失风险。

## 2. 产品目标

### 2.1 业务目标

| 目标 | 说明 |
| --- | --- |
| 提升首次记录完成率 | 用户进入 App 后能快速完成一次日运或抽牌手记 |
| 提升复盘率 | 用户能回到历史记录补充反馈，而不是只保存结果 |
| 提升长期沉淀感 | 用户能看到自己的牌义注疏、例证、小考档案逐渐积累 |
| 降低手机端操作负担 | 高频操作必须适配移动端，按钮触控面积和输入体验要可靠 |
| 增强作品集展示价值 | 产品结构、流程、原型、需求说明可以被清晰呈现 |

### 2.2 成功指标

| 指标 | 建议口径 |
| --- | --- |
| 日运完成率 | 触发日运抽牌后，完成第一直觉或今日回看的比例 |
| 手记保存率 | 进入抽牌手记后成功保存手记的比例 |
| 复盘补写率 | 已保存手记中填写用户复盘的比例 |
| 牌义沉淀量 | 用户编辑过牌义注疏或保存日运例证的牌数 |
| 小考参与度 | 小考作答次数、继续练习次数、待温习记录数 |
| 导出使用率 | 日运复盘、典籍复盘、牌义注疏的导出次数 |
| 同步成功率 | 登录用户的云端同步成功次数 / 同步尝试次数 |

## 6. 页面与导航结构

### 6.1 主要入口

| 入口 | 对应模块 | 用户目的 |
| --- | --- | --- |
| 启动页 | 用户中心 / 品牌入口 | 建立产品气质，进入研习台 |
| 研习台 | 日运研习、牌义小考、牌义注疏、典籍复盘 | 每日使用起点 |
| 记录 | 抽牌手记 | 新建或编辑抽牌记录 |
| 典籍 | 典籍复盘 | 回看、筛选、导出历史手记 |
| 广场 | 研习广场 | 浏览公开案例 |
| 侧边栏 | 用户中心 | 登录同步、资料设置、PWA 安装、数据状态 |

### 6.2 导航原则

1. 高频功能放在底部导航：研习台、记录、典籍、广场。
2. 低频账户能力放在侧边栏：登录、同步、资料、安全、PWA。
3. 首页不是功能列表，而是每日研习入口。
4. 牌义注疏和牌义小考可从首页进入，避免用户在学习场景中迷路。
5. 用户保存手记后优先回到典籍，强化“记录进入复盘库”的心智。

## 7. 功能需求

### 7.1 日运研习模块

#### 7.1.1 模块目标

帮助用户完成每日一张牌的轻量记录，并在当天或之后进行回看复盘，最终沉淀到日运复盘和牌义注疏中。

#### 7.1.2 功能需求

| 编号 | 需求 | 优先级 | 验收标准 |
| --- | --- | --- | --- |
| D-01 | 用户可在研习台抽取今日日运牌 | P0 | 点击洗牌/抽牌后生成今日牌、正逆位和解释 |
| D-02 | 用户可录入线下已抽到的现实牌 | P0 | 可选择牌名和正逆位，保存为今日牌 |
| D-03 | 今日记录拆分为“第一直觉”和“今日回看” | P0 | 两个字段分别保存，展示时保留换行 |
| D-04 | 同一天默认只保留一条今日日运 | P0 | 当日已有记录时再次进入显示已有牌，可修改或归档 |
| D-05 | 用户可将日运归档到日运复盘 | P0 | 归档后可在日运复盘中按时间线查看 |
| D-06 | 日运复盘支持时间线、按牌、本月视图 | P1 | 用户可按不同视角查看历史日运 |
| D-07 | 用户可导出日运复盘 | P1 | 支持 PDF / 表格等导出方式，文件名包含用户归属信息 |
| D-08 | 用户可将精选日运保存为牌义例证 | P1 | 保存后在对应单牌的牌义注疏中展示 |

#### 7.1.3 关键规则

1. 日运记录必须本地优先保存，云端失败不影响本地记录。
2. “第一直觉”和“今日回看”不可合并为单一字段。
3. 空状态文案保持温和，不给用户制造必须复盘的压力。
4. 完成记录后可温和触发 PWA 安装提示。

### 7.2 抽牌手记模块

#### 7.2.1 模块目标

支持用户记录一次完整的塔罗抽牌过程，包括问题、牌阵、牌面、正逆位、逐牌解读、复盘反馈和公开分享设置。

#### 7.2.2 功能需求

| 编号 | 需求 | 优先级 | 验收标准 |
| --- | --- | --- | --- |
| R-01 | 用户可选择记录对象：自己 / 客户 | P0 | 客户模式下必须填写客户称呼 |
| R-02 | 用户可填写占卜问题、日期、分类和标签 | P0 | 保存后在典籍中可检索和展示 |
| R-03 | 用户可选择官方牌阵或自定义牌阵 | P0 | 牌阵槽位、位置和标签与所选牌阵同步 |
| R-04 | 用户可编辑牌阵布局 | P0 | 支持官方牌阵恢复默认、自定义牌阵保存、自由布局坐标保存 |
| R-05 | 用户可逐槽录入牌面 | P0 | 每个槽位可选择牌、清空牌、切换正逆位 |
| R-06 | 用户可通过长按清空槽位 | P0 | 长按触发清空，支持触觉反馈，不误触普通点击 |
| R-07 | 用户可撤销牌面重排或误操作 | P0 | 操作历史可回退到上一步状态 |
| R-08 | 用户可填写逐牌解读和整体总结 | P0 | 保存前根据牌阵校验必要字段 |
| R-09 | 用户可生成 AI 解牌提示词 | P1 | 支持导师复盘和咨询解牌两种提示词模式 |
| R-10 | 用户可设置公开到广场或匿名分享 | P1 | 匿名分享时数据表现为公开且匿名 |
| R-11 | 用户可保存、编辑已有手记 | P0 | 新建保存后进入典籍；编辑保存后更新原记录 |

#### 7.2.3 校验规则

| 场景 | 校验 |
| --- | --- |
| 保存空手记 | 至少录入一张牌 |
| 普通手记 | 必须填写问题和牌阵 |
| 完整牌阵 | 不允许存在未录入牌面的槽位 |
| 客户模式 | 必须填写客户称呼 |
| 选择牌阵 | A 路和 B 路含义必须填写 |
| 生成导师提示词 | 需要用户自己的逐牌解读 |
| 生成咨询提示词 | 需要问题、牌阵和完整牌面 |

#### 7.2.4 关键规则

1. 牌阵定义、槽位标签、槽位位置必须保持同步。
2. 官方牌阵和自定义牌阵要区分管理，官方牌阵支持恢复默认。
3. 正逆位切换需支持多个入口：预览、状态标签、槽位快捷按钮。
4. 不使用系统 alert，错误和提示必须使用 Snackbar 或 Modal。

### 7.3 典籍复盘模块

#### 7.3.1 模块目标

将用户的抽牌手记沉淀为可回看、可筛选、可补复盘、可导出的个人典籍。

#### 7.3.2 功能需求

| 编号 | 需求 | 优先级 | 验收标准 |
| --- | --- | --- | --- |
| B-01 | 用户可查看私有手记列表 | P0 | 默认按更新时间或占卜时间倒序展示 |
| B-02 | 用户可按关键词搜索手记 | P0 | 问题、标签等字段可被检索 |
| B-03 | 用户可按复盘状态筛选 | P1 | 支持全部、已复盘、未复盘 |
| B-04 | 用户可按对象筛选 | P1 | 支持给自己、客户记录、指定客户 |
| B-05 | 用户可打开典籍索引 | P1 | 支持按牌、牌阵、用户标签、问题索引 |
| B-06 | 用户可查看手记详情 | P0 | 展示问题、牌阵、牌面、解读、复盘、反馈 |
| B-07 | 用户可编辑、删除或公开手记 | P0 | 删除需确认；公开状态可切换 |
| B-08 | 移动端支持长按进入多选 | P1 | 危险操作默认隐藏，进入多选后再显示删除 |
| B-09 | 用户可批量导出手记 | P1 | 支持 PDF、CSV、Markdown 等格式 |

#### 7.3.3 关键规则

1. 示例记录在用户已有真实记录后不应干扰筛选和索引。
2. 用户标签只能来自用户填写的标签，不把 AI 关键词当作筛选标签。
3. 移动端默认不裸露危险删除操作，避免误触。
4. 导出普通手记不应强制要求已复盘。

### 7.4 牌义注疏模块

#### 7.4.1 模块目标

为用户提供可长期维护的个人牌库，承接官方牌义、个人理解、体系对应、日运例证和历史关键词。

#### 7.4.2 功能需求

| 编号 | 需求 | 优先级 | 验收标准 |
| --- | --- | --- | --- |
| K-01 | 用户可查看 78 张塔罗牌 | P0 | 支持牌面、中文名、英文名展示 |
| K-02 | 用户可搜索或筛选牌 | P0 | 支持按名称、关键词、牌组等条件查找 |
| K-03 | 用户可查看官方牌义 | P0 | 展示正位、逆位、关键词和体系对应 |
| K-04 | 用户可编辑个人注疏 | P0 | 支持正位、逆位、关键词、个人笔记等字段 |
| K-05 | 用户可维护体系对应 | P1 | 支持灵数、元素、行星、星座、宫位等 |
| K-06 | 用户可查看日运例证 | P1 | 从日运复盘沉淀的记录展示在对应牌下 |
| K-07 | 用户可从小考补充关键词 | P1 | 小考答题后可给对应牌补关键词 |
| K-08 | 用户可导出牌义注疏 | P1 | 支持导出全部牌库或当前筛选结果 |

#### 7.4.3 关键规则

1. 牌义注疏是长期沉淀区，日运例证不能污染正逆位自由文本。
2. 功能命名使用“撰录成册”，不写成“转录成册”。
3. 导出入口保持轻量，不增加额外厚重工具区。

### 7.5 牌义小考模块

#### 7.5.1 模块目标

通过轻量小考帮助用户巩固牌面与体系对应关系，并将错题和不熟悉内容沉淀到待温习档案。

#### 7.5.2 功能需求

| 编号 | 需求 | 优先级 | 验收标准 |
| --- | --- | --- | --- |
| Q-01 | 首页展示一题轻量小考 | P0 | 用户无需进入复杂训练页即可作答 |
| Q-02 | 默认题型为看牌对应 | P0 | 通过牌面记忆元素、行星、星座、宫位等 |
| Q-03 | 支持文字找牌 | P1 | 用户可根据牌义文本选择对应牌 |
| Q-04 | 作答后展示答案反馈 | P0 | 展示正确答案和体系线索 |
| Q-05 | 错题或不熟悉题可进入待温习 | P0 | 待温习状态可在小考档案查看 |
| Q-06 | 小考档案展示历史记录 | P1 | 展示今日、累计、正确率、待温习、最近练习 |
| Q-07 | 用户可筛选练习范围 | P1 | 支持大阿卡纳、小阿卡纳、宫廷牌、元素等 |
| Q-08 | 用户可从小考补关键词 | P1 | 关键词保存到牌义注疏 |

#### 7.5.3 关键规则

1. 不做关键词单选题，避免多义牌义被误判为单一标准答案。
2. 答题后优先展示确定的体系线索，减少模糊联想文案。
3. 小考档案作为进阶入口，不在首页默认展开过多设置。

### 7.6 研习广场模块

#### 7.6.1 模块目标

让用户浏览公开手记，从他人的记录中获得牌阵和解读参考，同时支持用户将自己的手记公开或匿名分享到广场。

#### 7.6.2 功能需求

| 编号 | 需求 | 优先级 | 验收标准 |
| --- | --- | --- | --- |
| C-01 | 用户可查看公开手记列表 | P0 | 从云端读取公开记录并倒序展示 |
| C-02 | 云端读取失败时展示缓存 | P0 | 有缓存时提示“先展示上次保存的公开手记” |
| C-03 | 用户可查看公开手记详情 | P0 | 展示牌阵、牌面、解读等公开内容 |
| C-04 | 用户可按作者查看 | P1 | 点击作者后可聚焦相关公开记录或触发搜索 |
| C-05 | 用户可按标签查看 | P1 | 点击标签后可跳转到相关筛选 |
| C-06 | 用户可从手记设置公开 | P0 | 公开状态改变后广场可读取 |
| C-07 | 用户可匿名分享到广场 | P0 | 广场展示为匿名研习者，不暴露用户昵称 |

#### 7.6.3 关键规则

1. 公开分享必须由用户主动选择。
2. 匿名分享到广场在数据层为 `isPublic: true` 与 `isAnonymous: true`。
3. 研习广场不承担强社交功能，本期不做评论、私信、关注。

### 7.7 用户中心模块

#### 7.7.1 模块目标

承接账号、资料、安全、云端同步、PWA 安装和数据状态等全局能力，让用户在不登录时也能本地使用，登录后可同步云端。

#### 7.7.2 功能需求

| 编号 | 需求 | 优先级 | 验收标准 |
| --- | --- | --- | --- |
| U-01 | 用户可游客状态使用核心功能 | P0 | 未登录也可本地保存日运、手记、注疏、小考 |
| U-02 | 用户可注册、登录、退出登录 | P0 | 登录状态变化后界面和数据作用域正确 |
| U-03 | 支持邮箱验证提示 | P1 | 未验证邮箱时可发送验证邮件 |
| U-04 | 用户可编辑昵称、头像、简介 | P1 | 保存后更新作者名和资料展示 |
| U-05 | 用户可修改密码 | P1 | 密码强度校验和错误提示清晰 |
| U-06 | 用户可删除账户 | P1 | 删除前二次确认，删除后清理账号相关云端数据 |
| U-07 | 用户可手动云端同步 | P0 | 同步完成后展示状态和同步数量 |
| U-08 | 用户可添加到手机桌面 | P1 | 支持 PWA 安装提示，失败时给出温和反馈 |

#### 7.7.3 关键规则

1. 本地优先保存是默认策略，登录不是使用前置条件。
2. 云端同步失败不能影响用户本地记录。
3. 账户安全操作必须使用确认弹窗或明确提示，不使用系统 alert。
4. 删除账户属于高风险操作，必须二次确认。

## 10. 非功能需求

### 10.1 移动端体验

1. App 以手机端使用为优先。
2. 所有主要按钮触控面积不低于 44px。
3. 输入框聚焦时需避免被键盘遮挡。
4. 弹窗内容较多时必须可滚动。
5. 危险操作在移动端默认隐藏在确认或多选之后。

### 10.2 可用性

1. 核心记录流程不得强制登录。
2. 本地保存失败、云端同步失败、导出失败都需要有可理解提示。
3. 所有错误提示使用 Snackbar / Modal，不使用 `window.alert`。
4. 用户正在编辑的内容不得因切换页面或网络失败直接丢失。

### 10.3 性能

1. 初始页面优先加载首页核心内容。
2. 低频页面使用懒加载，减少首屏负担。
3. 牌面图片需要预加载或使用现代图片格式，减少闪烁。
4. 长列表使用渐进展示，避免一次性渲染过多卡片。

### 10.4 安全与隐私

1. 用户私有手记默认不公开。
2. 公开分享必须由用户主动操作。
3. 匿名公开时不展示用户昵称。
4. 埋点不上传正文、标签、客户姓名、问题内容等隐私字段。
5. 删除账户、删除记录、删除牌阵必须有确认机制。

### 10.5 视觉与品牌

1. 保持森林感和手札感，使用 `forest-*` 调色体系。
2. 标题使用 `font-serif` 和加粗，正文使用 `font-sans`。
3. 动效使用 `motion/react`，保留轻量入场和弹窗过渡。
4. 避免厚重卡片和过多嵌套卡片。
5. 产品文案保持温柔、短句、低压力，不做娱乐化算命口吻。

## 12. 风险与待确认

| 风险/问题 | 当前建议 |
| --- | --- |
| 公开广场是否需要互动能力 | 当前不做评论点赞，先保留公开案例浏览 |
| AI 辅助是否会让用户误以为 App 自动占卜 | 文案强调“提示词”和“辅助复盘”，不替代用户判断 |
| 牌义小考是否需要更多题型 | 先保留看牌对应和文字找牌，暂不做关键词单选 |
| 导出格式是否过多 | 作品集展示可保留 PDF / CSV / Markdown，后续看使用率收敛 |
| 自定义牌阵复杂度较高 | 牌阵编辑器作为核心亮点保留，但需要重点测试槽位同步和恢复默认 |
| 云端同步失败影响信任 | 本地优先、失败提示、手动同步是必须保留的安全感设计 |
