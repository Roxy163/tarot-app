# 塔罗研习阁项目记忆

这份文档给未来新的 Codex 对话窗口使用。开始处理本项目之前，先读 `AGENTS.md`，再读本文，避免让用户重复描述长期共识。

## 1. 产品一句话

“塔罗研习阁”是一个偏个人学习、记录、复盘和牌义沉淀的塔罗 Web / PWA 工具。它不是“算命娱乐 App”，而是陪用户把每日抽牌、牌阵手记、牌义注疏慢慢整理成自己的塔罗体系。

核心气质：温柔、安静、低压力、晨光手札感、森林感、轻透、秀气、可长期使用。

## 2. 用户最在意的体验原则

- 当前阶段先打磨功能、UI 和实际使用体验，暂不推进会员收费。用户在 2026-09-17 表示，除本人外仅看到 2 个邮箱注册用户，且观察到 VPN/注册门槛；不能据此直接判断市场规模或付费意愿，也不能把注册数当作全部使用人数。
- 2026-09-17 后续实测澄清：用户手机关闭 VPN 后，现有线上首页和邮箱登录均正常。用户没有自有域名或 ICP 备案。当前不把 VPN 视为已证实的普遍使用前提，也不据此默认要求购买域名或迁移后台。
- 手机端优先：用户常在手机上记录日运、补复盘、查看牌义。
- 紧凑但不拥挤：减少大留白、厚卡片、重复按钮；信息要一眼可读。
- 轻量而有质感：暖白、鼠尾草绿、淡粉点缀；少系统感，少“AI味”文案。
- 记录不能丢：本地优先保存，登录后云端同步；任何同步失败都不能影响本地数据。
- 可见改动先给本地预览；部署通常在用户明确说“部署”后进行。
- 不用 `window.alert`；用 Snackbar / Modal / 轻提示。
- 所有手机端按钮触控面积至少 44px。

## 3. 重要产品文案与调性

- App 名：塔罗研习阁
- 首屏 slogan：你的塔罗，自有体系。
- 功能说明：记录·注疏·布阵，构建你的个人手札。
- 首屏按钮：开启研习
- 底部小字：不教塔罗，只陪你成为自己的塔罗师。
- 登录游客兜底称号：优先使用温和、有归属感的称呼，不要太“系统默认”。
- 文案偏短、稳、温和；避免拟人化过度、过度可爱、太营销或太像 AI 生成。

## 4. 当前主要功能版图

### 研习台 / 首页

- 首屏进入后到研习台。
- 首页主入口应围绕日运：先抽日运，再把记录变成复盘。
- 顶部不要放容易误解的“写手记”主按钮；日运入口要比复盘入口更顺手。
- 牌义小考在首页直接出现一题，不要让用户先进入沉重训练面板。

### 日运

- 2026-09-18 已将首次记录体验改进与日常流程打磨一起部署；详情见 `docs/access-and-first-record-2026-09-17.md`、`docs/daily-flow-polish-2026-09-18.md`。欢迎页和登录页强调免注册，首页与日运档案补写共享按账号/记录隔离的草稿；仅成功保存后清理，本机写入失败保留表单。日运先读本机，云端返回必须合并最新内存状态，不能覆盖等待期间的编辑。
- 日运记录拆成两个字段：`第一直觉` / `今日回看`。
- 首页分块预览，保留用户输入的换行，不要把回车变成一个空格。
- 日运复盘支持时间线 / 按牌 / 本月，支持导出，支持归入牌义注疏里的“日运例证”区。
- 导出要有归属感：文件名包含用户昵称 + 日运复盘 + 日期。

### 抽牌手记

- `AddReadingForm` 是重点保护区，改动前必须看 `AGENTS.md`。
- 牌阵逻辑、自由画布、撤销、长按删除、正逆切换都不能破坏。
- 官方牌阵默认展示遵循“桌面摆牌密度”：像真实塔罗师在有限桌面上摆牌，牌与牌之间既不贴太近，也不拉出大块空白；每张牌完整可见，整体队形清楚。除凯尔特中心交叉等语义需要外，不加横纵线、圆线、连接线或背景结构线。
- 高级选项里“公开到研习广场”和“匿名分享到广场”是互斥 UI；匿名分享到广场在数据层应是 `isPublic: true` + `isAnonymous: true`。
- 标签复盘只能来自用户填写的标签，不要把 AI 生成关键词当用户标签。
- 普通手记不复盘也应能导出；导出/筛选尽量收在现有区域，避免额外大工具区。
- 手机典籍搜索独占一行，提供可见的多选入口；选中后导出。默认不露红色删除按钮，保留左滑和多选确认删除。卡片手势仅在横向拖动开始后捕获指针，不能在按下时抢走编辑按钮点击。
- 未完成手记按账号和记录自动暂存，保存成功或主动取消修改后才清除；切页、刷新和自由布局恢复不能覆盖草稿。
- 占卜日期与日运日期按本地日历处理；旧记录未改日期时保留原时间戳，避免反复编辑发生日期偏移。

### 牌义注疏 / 个人牌库

- 牌义注疏是用户长期沉淀的核心，不要用日运例证污染正逆位自由文本。
- “撰录成册”是正确功能名，不要写成“转录成册”。
- 导出应支持用户自由导出，并保持轻量入口。
- 批量牌义和个人注疏统一由 `cardAnnotationService` 本地优先保存，按账号隔离；云端通过 `users/{uid}/settings/cardAnnotations` 合并。旧全局本机资料只迁移给首个认领账号。
- 注疏编辑草稿与正式保存分开；本机写入失败必须保留编辑内容并提示，不能显示保存成功。重置操作带删除标记，防止旧设备同步复活已重置内容。

### 牌义小考

- 名称保持“牌义小考”，不要改成“牌义训练”。
- 首页默认题型：看牌面，记对应；用户通过视觉记忆牌面。
- 默认不展示“文字找牌”；文字找牌、专项筛选、复盘数据可放进“小考档案”。
- 不做关键词单选题，因为同一张牌可对应多个关键词，容易让用户觉得答案牵强。
- 答题后展示元素 / 行星 / 星座 / 宫位等体系线索，减少“也可联想到……”这类无必要补充。
- 选项文字别太粗，数字尽量用阿拉伯数字，如“第0宫”。

### PWA

- 目标：手机用户可添加到桌面，显示正确 App 图标和名称。
- 安装提醒适合在用户完成一次记录后温和提示，也可在侧边栏提供入口。
- 2026-09-18 后续改动已于 2026-09-19 发布：提醒“不再提醒”永久保存在当前浏览器，旧 14 天关闭记录同样生效；`appinstalled` / 独立模式启动记住已添加状态。菜单“添加到桌面”始终保留提醒开关与“我已添加到桌面”，不能因已安装就隐藏设置入口。详见 `docs/sidebar-and-install-reminders-2026-09-18.md`。

### 广场与启动体验

- 2026-09-19 已部署：公开手记、牌例、牌阵最近案例和管理列表接入完整公开阅读；禁止显示客户、私人复盘、AI 等私有字段，匿名昵称仍隐藏。列表轻量化，筛选/标签和次要操作收纳，手机单列、桌面双列，小图标保留 44px 触控区域；内置练习示例不进入广场。
- 新增云端点赞/撤销；规则已发布，18 项模拟器安全检查和 8 项真实云端检查通过，测试账号与点赞均清理。后续仍须先发布规则再发布对应网站。详见 `docs/public-square-and-startup-2026-09-19.md`。
- 启动用轻量“正在加载…”代替“恢复账号状态”；1.2 秒后显示慢连接解释，原有 2.2 秒本机兜底保留。不要用假进度条、额外欢迎步骤或无期限登录等待。已知账号隔离与后台恢复连接不可破坏。

## 6. 视觉方向

- 保持 `forest-*` Tailwind 主题。
- 背景偏暖白奶油色，卡片可半透明，弱边框、弱阴影。
- 减少“卡片套卡片套卡片”。
- 同一区块里的同级小卡片要保持同一种底色/边框体系，不要用粉、绿、米色混排到像状态错乱。
- 装饰纹样只适合放在大背景、大区块或远离操作按钮的位置；小卡片、统计卡、按钮附近不要放水印花纹。
- 用户说“简化/轻量化”时，含义是减少厚重感和冗余，不是删掉精心设计的 UI 氛围、花纹、层次和品牌感。

## 7. Codex 工作方式

- 开工先看 `git status --short`；不要回退用户已有改动。
- 搜索用 `rg`。
- 编辑用 `apply_patch`。
- 可见 UI 改动后，默认启动/确认本地预览，并给用户本地地址；必要时补手机端截图。除非用户明确说不用预览。
- 部署前至少跑：
  - `npm run lint`
  - `npm test` 或相关测试
  - `npm run build`
  - 必要时 Playwright 真实交互验收
- 不要为一个小 bug 大重构；除非用户明确要求“整体重构”。
- 如果同类 UI 问题重复出现，先查项目记忆和最近截图需求，再做小范围修正；批量阅览、手机端紧凑、危险操作隐藏是固定验收项，不要每次重新讨论。

## 8. 用户以后开新窗口时的高效说法

用户可以直接这样开头：

```text
这是塔罗研习阁项目。请先读 AGENTS.md 和 docs/tarot-app-project-memory.md，再继续。
这次我要改：……
是否需要部署：是 / 否
验收重点：手机端 / 电脑端 / 云端同步 / 导出 / 视觉
```

如果是 bug，最好补三点：

```text
哪里出问题：
我期望它怎么表现：
截图或复现步骤：
```

如果是审美优化，最好补三点：

```text
觉得哪里别扭：
希望更接近：轻透 / 紧凑 / 稳重 / 有趣 / 更像手札
哪些东西不要动：
```
