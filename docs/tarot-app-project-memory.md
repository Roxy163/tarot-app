# 塔罗研习阁项目记忆

这份文档给未来新的 Codex 对话窗口使用。开始处理本项目之前，先读 `AGENTS.md`，再读本文，避免让用户重复描述长期共识。

## 1. 产品一句话

“塔罗研习阁”是一个偏个人学习、记录、复盘和牌义沉淀的塔罗 Web / PWA 工具。它不是“算命娱乐 App”，而是陪用户把每日抽牌、牌阵手记、牌义注疏慢慢整理成自己的塔罗体系。

核心气质：温柔、安静、低压力、晨光手札感、森林感、轻透、秀气、可长期使用。

## 2. 用户最在意的体验原则

- 手机端优先：用户常在手机上记录日运、补复盘、查看牌义。
- 紧凑但不拥挤：减少大留白、厚卡片、重复按钮；信息要一眼可读。
- 轻量而有质感：暖白、鼠尾草绿、淡粉点缀；少系统感，少“AI味”文案。
- 记录不能丢：本地优先保存，登录后云端同步；任何同步失败都不能影响本地数据。
- 可见改动先给本地预览；部署通常在用户明确说“部署”后进行。
- 不用 `window.alert`；用 Snackbar / Modal / 轻提示。
- 所有手机端按钮触控面积至少 44px。

## 3. 重要产品文案与调性

- App 名：塔罗研习阁
- 首屏 slogan：你的塔罗，自有体系。
- 功能说明：记录·注疏·布阵，构建你的个人手札。
- 首屏按钮：开启研习
- 底部小字：不教塔罗，只陪你成为自己的塔罗师。
- 登录游客兜底称号：优先使用温和、有归属感的称呼，不要太“系统默认”。
- 文案偏短、稳、温和；避免拟人化过度、过度可爱、太营销或太像 AI 生成。

## 4. 当前主要功能版图

### 研习台 / 首页

- 首屏进入后到研习台。
- 首页主入口应围绕日运：先抽日运，再把记录变成复盘。
- 顶部不要放容易误解的“写手记”主按钮；日运入口要比复盘入口更顺手。
- 牌义小考在首页直接出现一题，不要让用户先进入沉重训练面板。

### 日运

- 日运记录拆成两个字段：`第一直觉` / `今日回看`。
- 首页分块预览，保留用户输入的换行，不要把回车变成一个空格。
- 日运复盘支持时间线 / 按牌 / 本月，支持导出，支持归入牌义注疏里的“日运例证”区。
- 导出要有归属感：文件名包含用户昵称 + 日运复盘 + 日期。

### 抽牌手记

- `AddReadingForm` 是重点保护区，改动前必须看 `AGENTS.md`。
- 牌阵逻辑、自由画布、撤销、长按删除、正逆切换都不能破坏。
- 高级选项里“公开到研习广场”和“匿名分享到广场”是互斥 UI；匿名分享到广场在数据层应是 `isPublic: true` + `isAnonymous: true`。
- 标签复盘只能来自用户填写的标签，不要把 AI 生成关键词当用户标签。
- 普通手记不复盘也应能导出；导出/筛选尽量收在现有区域，避免额外大工具区。

### 牌义注疏 / 个人牌库

- 牌义注疏是用户长期沉淀的核心，不要用日运例证污染正逆位自由文本。
- “撰录成册”是正确功能名，不要写成“转录成册”。
- 导出应支持用户自由导出，并保持轻量入口。

### 牌义小考

- 名称保持“牌义小考”，不要改成“牌义训练”。
- 首页默认题型：看牌面，记对应；用户通过视觉记忆牌面。
- 默认不展示“文字找牌”；文字找牌、专项筛选、复盘数据可放进“小考档案”。
- 不做关键词单选题，因为同一张牌可对应多个关键词，容易让用户觉得答案牵强。
- 答题后展示元素 / 行星 / 星座 / 宫位等体系线索，减少“也可联想到……”这类无必要补充。
- 选项文字别太粗，数字尽量用阿拉伯数字，如“第0宫”。

### PWA

- 目标：手机用户可添加到桌面，显示正确 App 图标和名称。
- 安装提醒适合在用户完成一次记录后温和提示，也可在侧边栏提供入口。

## 5. 云端与部署记忆

- Firebase Project ID：`tarot-pavilion`。
- Firestore Rules 发布：`npx --yes firebase-tools deploy --only firestore:rules --project tarot-pavilion`。
- Firebase CLI 授权容易失败；不要反复消耗用户复制 code。失败后按 `docs/firebase-deployment-runbook.md` 处理。
- 当前临时/常用部署：Cloudflare Pages。
- Cloudflare Pages 发布通常：
  - `npm run build`
  - `npx wrangler pages deploy dist`
- 需要确认主地址和新预览地址是否返回 200。
- 不启用 Firebase Storage，避免付费依赖。

## 6. 视觉方向

- 保持 `forest-*` Tailwind 主题。
- 背景偏暖白奶油色，卡片可半透明，弱边框、弱阴影。
- 减少“卡片套卡片套卡片”。
- 同一区块里的同级小卡片要保持同一种底色/边框体系，不要用粉、绿、米色混排到像状态错乱。
- 装饰纹样只适合放在大背景、大区块或远离操作按钮的位置；小卡片、统计卡、按钮附近不要放水印花纹。
- 用户说“简化/轻量化”时，含义是减少厚重感和冗余，不是删掉精心设计的 UI 氛围、花纹、层次和品牌感。
- 标题用 `font-serif`，正文用 `font-sans`。
- 弹窗要轻：少厚边框、少大留白、能滚动，不能挡住用户查看正文。
- 底部导航保持固定在底部，轻薄一点，不要放“印鉴”。
- 侧边栏只放必要功能，删除重复登录入口和主页面已有的重复功能。
- 典籍、复盘、牌义库等批量阅览页：默认态不要裸露红色删除等危险操作；删除应放在长按/多选/确认之后。外层优先保留“查看、编辑、分享”等低风险高频操作，避免手机端误触。

## 7. Codex 工作方式

- 开工先看 `git status --short`；不要回退用户已有改动。
- 搜索用 `rg`。
- 编辑用 `apply_patch`。
- 可见 UI 改动后，默认启动/确认本地预览，并给用户本地地址；必要时补手机端截图。除非用户明确说不用预览。
- 部署前至少跑：
  - `npm run lint`
  - `npm test` 或相关测试
  - `npm run build`
  - 必要时 Playwright 真实交互验收
- 不要为一个小 bug 大重构；除非用户明确要求“整体重构”。
- 如果同类 UI 问题重复出现，先查项目记忆和最近截图需求，再做小范围修正；批量阅览、手机端紧凑、危险操作隐藏是固定验收项，不要每次重新讨论。

## 8. 用户以后开新窗口时的高效说法

用户可以直接这样开头：

```text
这是塔罗研习阁项目。请先读 AGENTS.md 和 docs/tarot-app-project-memory.md，再继续。
这次我要改：……
是否需要部署：是 / 否
验收重点：手机端 / 电脑端 / 云端同步 / 导出 / 视觉
```

如果是 bug，最好补三点：

```text
哪里出问题：
我期望它怎么表现：
截图或复现步骤：
```

如果是审美优化，最好补三点：

```text
觉得哪里别扭：
希望更接近：轻透 / 紧凑 / 稳重 / 有趣 / 更像手札
哪些东西不要动：
```
