## 优先处理的内容保护问题

### 1. 重排位置序号后，逐牌解读和疑问错绑

- **已修复**：牌位重排、删除、长按清空及撤销同步处理牌面、标签、坐标、逐牌解读和疑问。撤销使用完整编辑快照，随草稿保存；兼容旧草稿与历史，不改已确认的官方几何和用户保存坐标。
- 复现：给太阳和隐士分别填写独有解读、疑问 → 编辑当前牌阵 → 把第二位置序号改为 1 → 保存牌阵 → 返回逐牌研习 → 保存手记。
- 实测：第一张变成隐士，但其解读和疑问仍是太阳的文字。提交回调收到的数据也保留了这个错误对应。
- 原因：`AddReadingForm.tsx:801–805` 只移动 `cardSlots`；`cardInterpretations/cardQuestions` 未随对象移动。撤销同样只保存卡槽数组，修复时须一起核对整组历史与草稿。
- 建议：序号调整、删除和撤销都同步处理牌面、标签、坐标、逐牌解读、疑问，保持相同实体的对应，不改用户几何。

### 2. “恢复官方”会立即清掉两类个人笔记

- **已修复**：恢复前明确确认范围，只恢复灵数、行星、星座、宫位、元素、关键词和正逆位释义；保留已保存及正在填写的个人笔记、日运例证。本机写入失败时保留原注解和当前输入，提示后可以重试。
- 复现：保存资料页“我的牌义笔记”和编辑页“个人注解” → 在编辑页另写草稿 → 点击“恢复官方”。
- 实测：不弹确认、不需要再保存；两类已保存文字和当前编辑草稿即被清除，返回资料页后笔记为空。
- 原因：`CardAnnotationEditor.tsx:169–179` 直接调用 `cardAnnotationService.resetAnnotationToOfficial`，后者删除整条用户注疏，而不是只恢复官方释义字段。
- 建议：明确恢复范围，保留个人笔记，存在修改时先确认，并给出恢复路径。

### 3. 工作台切模板或新建空白，直接替换未保存设计

- **已修复**：工作台切模板或新建空白，在替换当前未保存设计前确认，支持完整撤销；工作台草稿与原始快照一并暂存，重开后仍能继续或取消。应用较少位置且会移除已有牌面或文字时另行确认；取消返回原手记和原摆牌。
- 复现：工作台把位置标签改为独有文字 → 下拉选择另一个模板，或点击“新建空白”。
- 实测：均无确认，当前草稿变成新模板的空白位置或 0 个位置，独有设计消失。这里只确认当前未保存设计被替换，未声称正式保存的原手记被删除。
- 原因：`SpreadDesigner.tsx:141–156/237–244` 直接调用切换；`AddReadingForm.tsx:912–922/1321–1333` 直接替换卡槽，没有走已有完整切换快照与确认逻辑。
- 建议：工作台内切换也保留切换前完整快照，提示放弃未保存设计，并支持撤销。

## 查找与批量处理的不便

### 4. 典籍编辑返回后丢失浏览状态

- **已修复**：从典籍编辑已有记录时保留来源组件、搜索／标签／状态／客户／索引筛选、网格或列表视图、多选及已展开条数；保存、取消和系统返回恢复原滚动位置。来源按账号隔离；新增手记继续沿用原有导航，不套用旧记录的来源位置。
- 触发：筛选已复盘/客户/牌阵索引，切列表并翻到旧记录 → 编辑 → 保存或取消。
- 代码确认：进入编辑会卸载 `PrivateTab`；状态筛选、索引、列表视图、多选和渐进加载进度均在组件本地，返回重建默认值。保存还主动清空搜索和标签，导航滚回页首。
- 组件验证：真实点击筛选“已复盘”和“列表”，在模拟 App 条件挂载的夹具中卸载/重挂，确实恢复全部/网格；这不是完整浏览器编辑路线验证。
- 位置：`PrivateTab.tsx:108–119`，`App.tsx:594–600/1060–1080/1827–1853`。
- 建议：保留来源列表状态，返回原记录附近；新增手记与修改旧手记分别处理导航。

### 5. 跨搜索结果无法累积多选

- **已修复**：以全部现存真实记录维护选择，跨搜索、筛选及空结果保留已选项；分别显示已选总数、当前结果和结果外的选择数。导出包含全部已选记录；全选／取消当前选择只影响当前结果，主动清空或记录被删除时才移除对应选择。
- 复现：搜索甲记录并选中 → 搜索乙记录再选中 → 清空搜索。
- 实测：甲已被自动取消，最后只剩乙，导出数量为 1。清空筛选不会恢复原选择。
- 原因：`PrivateTab.tsx:196–216` 以当前筛选结果计算选择，并永久移除当前结果外的 ID。
- 建议：以全部现存记录维护已选 ID，独立显示当前结果和已选总数；“全选当前”只影响当前范围，主动取消才移除。

### 6. 旧日运缺少日期与文字定位

- **已修复**：日运抽牌和日运手记各自支持牌名、文字和常见日期格式搜索，并提供可展开的日期／月份输入与清空查找。“本月”改为“按月”，可选择历史月份；列表、当前结果、月度统计和导出共用相同筛选结果。来源切换及关闭重开保留各自查找条件；日期显示、筛选和排序使用本地日历，手记兼容 `readingDate/date`。
- 代码确认：“日运抽牌”只有状态、按牌和固定当前月份的“本月”；文字搜索只在“日运手记”来源。想找过去某日或写过“面试”的日运，需要长滚或记住具体牌名。
- 手记文字搜索同样未纳入 `readingDate/date`，页面显示的日期不能直接作为检索依据。
- 位置：`DailyFortuneArchiveModal.tsx:472–483/774–794/816–820`，`readingSearch.ts:15–22`。
- 建议：提供可见日期/月份筛选；两类日运都支持内容检索，同时保留来源区别。

### 7. 两个相近的个人笔记入口互相看不到

- **已修复**：资料页与牌义编辑页统一为“我的牌义笔记”，共享正式内容和按账号／牌面隔离的草稿。旧 `personalMeaning/personalNotes` 的不同原文完整保留并合并展示，相同文字不重复；只有用户明确保存才统一写回。保存失败保留草稿，导出使用同一完整笔记。
- 复现：资料页“我的牌义笔记”保存 → 编辑这张牌义 → “个人注解”为空；从编辑页保存后回资料页也看不到该文字。
- 实测：两边都保存成功，但分别写入 `personalMeaning` 和 `personalNotes`，用户容易误认为保存失败或丢内容。
- 位置：`CardMetadataManager.tsx:335–338/564/1076`，`CardAnnotationEditor.tsx:35/148/483–491`。
- 建议：统一查看入口或明确区分用途；若合并，先完整保留两边的原文，不能覆盖。
