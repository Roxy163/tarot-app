## 1. 产品概述

### 1.1 产品定位

塔罗研习阁是一款面向塔罗学习者的个人研习工具，帮助用户完成日运记录、抽牌手记、典籍复盘、牌义注疏、牌义小考和公开案例浏览。

产品不以一次性算命结果为核心，而是围绕“记录 - 回看 - 复盘 - 沉淀 - 再练习”的长期学习过程展开。它更接近一套个人塔罗手札系统，帮助用户把零散的抽牌经验、牌义理解和复盘材料逐步整理成自己的学习体系。

### 1.2 产品一句话

记录、注疏、布阵，构建你的个人塔罗手札。

### 1.3 核心价值

| 价值点 | 说明 |
| --- | --- |
| 降低记录成本 | 让用户可以快速记录每日抽牌、普通手记和线下抽牌结果 |
| 强化复盘习惯 | 日运和普通手记都支持后续回看，避免记录停留在一次性保存 |
| 沉淀个人牌义 | 将个人注疏、日运例证、关键词和体系对应沉淀到牌义库 |
| 提供轻量练习 | 通过牌义小考帮助用户巩固牌面、元素、行星、星座、宫位等记忆 |
| 保持数据安全感 | 本地优先保存，登录后支持云端同步，网络失败不影响本地记录 |
| 适配手机使用 | 高频功能优先考虑移动端输入、触控和快速回看场景 |

### 1.4 目标用户

| 用户类型 | 典型需求 | 产品回应 |
| --- | --- | --- |
| 塔罗初学者 | 想记录每日抽牌和练习过程，但缺少系统方法 | 提供日运、抽牌手记、牌义小考和牌义注疏 |
| 进阶学习者 | 想复盘历史案例，形成自己的牌义理解 | 提供典籍索引、筛选、导出和个人牌库 |
| 为他人占卜的用户 | 需要区分个人记录与客户记录，并保留反馈 | 抽牌手记支持客户模式和客户反馈 |
| 手机端高频用户 | 想在日常场景中快速记录，不希望流程过重 | PWA、移动端优先、日运快捷入口 |
| AI 辅助使用者 | 不知道如何把抽牌上下文整理给 AI | 提供结构化解牌提示词和关键词整理辅助 |

## 2. 产品目标

### 2.1 业务目标

| 目标 | 说明 |
| --- | --- |
| 提升首次记录完成率 | 用户进入产品后，能快速完成一次日运或抽牌手记 |
| 提升复盘率 | 用户能回到历史记录中补充反馈，而不是只保存抽牌结果 |
| 提升长期沉淀感 | 用户能看到自己的牌义注疏、日运例证和小考档案逐渐积累 |
| 降低手机端操作负担 | 高频操作在移动端应足够顺手，按钮、输入框和弹窗都要适配触控 |
| 降低需求理解偏差 | 通过明确范围、规则和验收标准，让后续设计、开发、测试围绕同一目标推进 |

### 2.2 成功指标

以下指标用于衡量产品方向是否有效。当前版本先定义统计口径，具体目标值可在上线或可用性测试后根据基线数据补充。

| 指标 | 统计口径 |
| --- | --- |
| 日运完成率 | 触发日运抽牌后，填写“第一直觉”或“今日回看”的比例 |
| 手记保存率 | 进入抽牌手记后，成功保存手记的比例 |
| 复盘补写率 | 已保存手记中，后续填写用户复盘的比例 |
| 牌义沉淀量 | 用户编辑过牌义注疏，或保存过日运例证的牌数 |
| 小考参与度 | 小考作答次数、继续练习次数、待温习记录数 |
| 导出使用率 | 日运复盘、典籍复盘、牌义注疏的导出次数 |
| 同步成功率 | 登录用户云端同步成功次数 / 同步尝试次数 |

## 3. 需求范围

### 3.1 本期范围

| 模块 | 范围 |
| --- | --- |
| 日运研习 | 日运抽牌、现实牌录入、第一直觉、今日回看、归档、日运复盘、导出、归入注疏 |
| 抽牌手记 | 个人 / 客户记录、牌阵选择、牌面录入、正逆位、逐牌解读、AI 提示词、公开 / 匿名设置、保存 |
| 典籍复盘 | 私有手记列表、搜索筛选、典籍索引、详情查看、复盘补写、多选、导出 |
| 牌义注疏 | 78 张牌库、官方牌义、个人注疏、关键词、体系对应、日运例证、导出 |
| 牌义小考 | 看牌对应、文字找牌、答题反馈、待温习、小考档案 |
| 研习广场 | 公开手记浏览、公开 / 匿名分享、作者 / 标签查看、离线缓存兜底 |
| 用户中心 | 登录注册、邮箱验证、资料设置、账号安全、退出登录、删除账户、云端同步、PWA 安装入口 |

### 3.2 暂不纳入范围

| 功能 | 暂不纳入原因 |
| --- | --- |
| 在线支付 / 会员体系 | 当前版本以核心记录和复盘体验验证为主 |
| 评论、点赞、关注关系 | 研习广场先验证公开案例浏览，不扩展复杂社区关系 |
| 复杂 AI 在线对话 | 当前 AI 主要作为提示词生成和关键词整理辅助 |
| 多人协作牌阵编辑 | 产品优先服务个人学习，协作场景暂不展开 |
| 第三方登录全覆盖 | 现阶段以邮箱登录和本地游客使用为主 |

### 3.3 优先级说明

| 优先级 | 定义 |
| --- | --- |
| P0 | 核心路径，缺失后会影响主要使用流程 |
| P1 | 重要体验，建议在基础流程稳定后补齐 |
| P2 | 增强功能，可根据时间和验证结果延后 |

## 5. 页面与导航结构

### 5.1 主要入口

| 入口 | 对应模块 | 用户目的 |
| --- | --- | --- |
| 启动页 | 用户中心 / 品牌入口 | 建立产品气质，进入研习台 |
| 研习台 | 日运研习、牌义小考、牌义注疏、典籍复盘 | 每日使用起点 |
| 记录 | 抽牌手记 | 新建或编辑抽牌记录 |
| 典籍 | 典籍复盘 | 回看、筛选、导出历史手记 |
| 广场 | 研习广场 | 浏览公开案例 |
| 侧边栏 | 用户中心 | 登录同步、资料设置、PWA 安装、数据状态 |

### 5.2 导航原则

- 高频功能放在底部导航：研习台、记录、典籍、广场。
- 低频账户能力放在侧边栏：登录、同步、资料、安全、PWA。
- 首页不是功能列表，而是每日研习入口。
- 牌义注疏和牌义小考可从首页进入，减少学习场景中的跳转成本。
- 用户保存手记后优先回到典籍，强化“记录进入复盘库”的心智。

## 6. 功能需求

### 6.1 日运研习模块

#### 6.1.1 模块目标

帮助用户完成每日一张牌的轻量记录，并在当天或之后进行回看复盘。日运记录既可以作为当天练习，也可以沉淀到日运复盘和牌义注疏中。

#### 6.1.2 功能需求

| 需求 | 优先级 | 验收标准 |
| --- | --- | --- |
| 用户可在研习台抽取今日日运牌 | P0 | 当用户点击洗牌 / 抽牌后，系统生成今日牌、正逆位和对应解释；抽取结果可保存为当天日运 |
| 用户可录入线下已抽到的现实牌 | P0 | 用户可选择牌名和正逆位，并将其保存为当天日运牌 |
| 今日记录拆分为“第一直觉”和“今日回看” | P0 | 两个字段分别保存；展示时保留用户输入的换行 |
| 同一天默认只保留一条日运记录 | P0 | 当天已有记录时，再次进入日运模块应展示已有记录，并允许修改或归档 |
| 用户可将日运归档到日运复盘 | P0 | 归档后，该记录可在日运复盘中查看 |
| 日运复盘支持时间线、按牌、本月视图 | P1 | 用户可按不同视角查看历史日运记录 |
| 用户可导出日运复盘 | P1 | 支持 PDF / CSV / Markdown 等导出方式；文件名需包含用户归属信息 |
| 用户可将精选日运保存为牌义例证 | P1 | 保存后，记录应出现在对应单牌的牌义注疏中 |

#### 6.1.3 规则与边界

- 日运记录必须本地优先保存，云端同步失败不能影响本地记录。
- “第一直觉”和“今日回看”不可合并为单一字段。
- 空状态文案保持温和，不给用户制造必须复盘的压力。
- 完成记录后可温和触发 PWA 安装提示。
- 保存失败时保留当前输入内容，并使用 Snackbar 或 Modal 提示。

### 6.2 抽牌手记模块

#### 6.2.1 模块目标

支持用户记录一次完整的塔罗抽牌过程，包括问题、牌阵、牌面、正逆位、逐牌解读、复盘反馈和公开分享设置。该模块是产品中最复杂的记录入口，需要优先保证牌阵、槽位和保存逻辑稳定。

#### 6.2.2 功能需求

| 需求 | 优先级 | 验收标准 |
| --- | --- | --- |
| 用户可选择记录对象：自己 / 客户 | P0 | 选择客户模式后，保存前必须填写客户称呼 |
| 用户可填写占卜问题、日期、分类和标签 | P0 | 保存后，相关字段可在典籍中检索和展示 |
| 用户可选择官方牌阵或自定义牌阵 | P0 | 切换牌阵后，槽位数量、位置和标签应与所选牌阵同步 |
| 用户可编辑牌阵布局 | P0 | 官方牌阵支持恢复默认；自定义牌阵支持保存；自由布局坐标应准确保存 |
| 用户可逐槽录入牌面 | P0 | 每个槽位可选择牌、清空牌、切换正逆位 |
| 用户可通过长按清空槽位 | P0 | 长按约 600ms 后触发清空，支持触觉反馈，不应误触普通点击 |
| 用户可撤销牌面重排或误操作 | P0 | 操作历史可回退到上一步状态 |
| 用户可填写逐牌解读和整体总结 | P0 | 保存前根据牌阵和记录类型校验必要字段 |
| 用户可生成 AI 解牌提示词 | P1 | 支持导师复盘和咨询解牌两种提示词模式 |
| 用户可设置公开到广场或匿名分享 | P1 | 匿名分享时，数据层应表现为公开且匿名 |
| 用户可保存新手记或编辑已有手记 | P0 | 新建保存后进入典籍；编辑保存后更新原记录，不创建重复记录 |

#### 6.2.3 校验规则

| 场景 | 校验 |
| --- | --- |
| 保存空手记 | 至少录入一张牌 |
| 普通手记 | 必须填写问题和牌阵 |
| 完整牌阵 | 不允许存在未录入牌面的槽位 |
| 客户模式 | 必须填写客户称呼 |
| 选择 A / B 路牌阵 | A 路和 B 路含义必须填写 |
| 生成导师提示词 | 需要用户自己的逐牌解读 |
| 生成咨询提示词 | 需要问题、牌阵和完整牌面 |

#### 6.2.4 规则与边界

- 牌阵定义、槽位标签、槽位位置必须保持同步。
- 官方牌阵和自定义牌阵要区分管理，官方牌阵支持恢复默认。
- 正逆位切换需支持多个入口：预览、状态标签、槽位快捷按钮。
- 错误和提示必须使用 Snackbar 或 Modal，不使用系统 alert。
- 用户正在编辑时，切换页面或网络失败不应直接丢失内容。

### 6.3 典籍复盘模块

#### 6.3.1 模块目标

将用户的抽牌手记沉淀为可回看、可筛选、可补复盘、可导出的个人典籍。该模块承担“记录之后还能被使用”的责任。

#### 6.3.2 功能需求

| 需求 | 优先级 | 验收标准 |
| --- | --- | --- |
| 用户可查看私有手记列表 | P0 | 默认按更新时间或占卜时间倒序展示 |
| 用户可按关键词搜索手记 | P0 | 占卜问题、用户标签等字段可被检索 |
| 用户可按复盘状态筛选 | P1 | 支持全部、已复盘、未复盘 |
| 用户可按对象筛选 | P1 | 支持给自己、客户记录、指定客户 |
| 用户可打开典籍索引 | P1 | 支持按牌、牌阵、用户标签、问题索引 |
| 用户可查看手记详情 | P0 | 详情页展示问题、牌阵、牌面、解读、复盘、反馈 |
| 用户可编辑、删除或公开手记 | P0 | 删除前必须确认；公开状态可切换 |
| 移动端支持长按进入多选 | P1 | 危险操作默认隐藏，进入多选后再显示删除 |
| 用户可批量导出手记 | P1 | 支持 PDF / CSV / Markdown 等格式 |

#### 6.3.3 规则与边界

- 示例记录在用户已有真实记录后，不应干扰筛选和索引。
- 用户标签只能来自用户填写的标签，不把 AI 生成关键词当作筛选标签。
- 移动端默认不裸露危险删除操作，避免误触。
- 导出普通手记不应强制要求已复盘。
- 删除记录后，列表、索引和公开状态应同步更新。

### 6.4 牌义注疏模块

#### 6.4.1 模块目标

为用户提供可长期维护的个人牌库，承接官方牌义、个人理解、体系对应、日运例证和历史关键词。

#### 6.4.2 功能需求

| 需求 | 优先级 | 验收标准 |
| --- | --- | --- |
| 用户可查看 78 张塔罗牌 | P0 | 支持牌面、中文名、英文名展示 |
| 用户可搜索或筛选牌 | P0 | 支持按名称、关键词、牌组等条件查找 |
| 用户可查看官方牌义 | P0 | 展示正位、逆位、关键词和体系对应 |
| 用户可编辑个人注疏 | P0 | 支持正位、逆位、关键词、个人笔记等字段 |
| 用户可维护体系对应 | P1 | 支持灵数、元素、行星、星座、宫位等 |
| 用户可查看日运例证 | P1 | 从日运复盘沉淀的记录展示在对应牌下 |
| 用户可从小考补充关键词 | P1 | 小考答题后可给对应牌补关键词 |
| 用户可导出牌义注疏 | P1 | 支持导出全部牌库或当前筛选结果 |

#### 6.4.3 规则与边界

- 牌义注疏是长期沉淀区，日运例证不能污染正逆位自由文本。
- 功能命名使用“撰录成册”，不写成“转录成册”。
- 导出入口保持轻量，不增加额外厚重工具区。
- 用户编辑个人注疏失败时，应保留输入内容并提示失败原因。

### 6.5 牌义小考模块

#### 6.5.1 模块目标

通过轻量小考帮助用户巩固牌面与体系对应关系，并将错题和不熟悉内容沉淀到待温习档案。

#### 6.5.2 功能需求

| 需求 | 优先级 | 验收标准 |
| --- | --- | --- |
| 首页展示一题轻量小考 | P0 | 用户无需进入复杂训练页即可作答 |
| 默认题型为看牌对应 | P0 | 通过牌面记忆元素、行星、星座、宫位等 |
| 支持文字找牌 | P1 | 用户可根据牌义文本选择对应牌 |
| 作答后展示答案反馈 | P0 | 展示正确答案和体系线索 |
| 错题或不熟悉题可进入待温习 | P0 | 待温习状态可在小考档案查看 |
| 小考档案展示历史记录 | P1 | 展示今日、累计、正确率、待温习、最近练习 |
| 用户可筛选练习范围 | P1 | 支持大阿卡纳、小阿卡纳、宫廷牌、元素等 |
| 用户可从小考补关键词 | P1 | 关键词保存到牌义注疏 |

#### 6.5.3 规则与边界

- 不做关键词单选题，避免多义牌义被误判为单一标准答案。
- 答题后优先展示确定的体系线索，减少模糊联想文案。
- 小考档案作为进阶入口，不在首页默认展开过多设置。
- 错题和不熟悉题的状态应允许后续复习和更新。

### 6.6 研习广场模块

#### 6.6.1 模块目标

让用户浏览公开手记，从他人的记录中获得牌阵和解读参考。同时支持用户将自己的手记公开或匿名分享到广场。

#### 6.6.2 功能需求

| 需求 | 优先级 | 验收标准 |
| --- | --- | --- |
| 用户可查看公开手记列表 | P0 | 从云端读取公开记录并倒序展示 |
| 云端读取失败时展示缓存 | P0 | 有缓存时提示“先展示上次保存的公开手记” |
| 用户可查看公开手记详情 | P0 | 展示牌阵、牌面、解读等公开内容 |
| 用户可按作者查看 | P1 | 点击作者后可聚焦相关公开记录或触发搜索 |
| 用户可按标签查看 | P1 | 点击标签后可跳转到相关筛选 |
| 用户可从手记设置公开 | P0 | 公开状态改变后，广场可读取该记录 |
| 用户可匿名分享到广场 | P0 | 广场展示为匿名研习者，不暴露用户昵称 |

#### 6.6.3 规则与边界

- 公开分享必须由用户主动选择。
- 匿名分享到广场在数据层为 `isPublic: true` 与 `isAnonymous: true`。
- 研习广场不承担强社交功能，本期不做评论、私信、关注。
- 私有手记默认不进入广场。

### 6.7 用户中心模块

#### 6.7.1 模块目标

承接账号、资料、安全、云端同步、PWA 安装和数据状态等全局能力。用户不登录也能本地使用，登录后可将数据同步到云端。

#### 6.7.2 功能需求

| 需求 | 优先级 | 验收标准 |
| --- | --- | --- |
| 用户可游客状态使用核心功能 | P0 | 未登录也可本地保存日运、手记、注疏、小考 |
| 用户可注册、登录、退出登录 | P0 | 登录状态变化后，界面和数据作用域正确 |
| 支持邮箱验证提示 | P1 | 未验证邮箱时可发送验证邮件 |
| 用户可编辑昵称、头像、简介 | P1 | 保存后更新作者名和资料展示 |
| 用户可修改密码 | P1 | 密码强度校验和错误提示清晰 |
| 用户可删除账户 | P1 | 删除前二次确认；删除后清理账号相关云端数据 |
| 用户可手动云端同步 | P0 | 同步完成后展示状态和同步数量 |
| 用户可添加到手机桌面 | P1 | 支持 PWA 安装提示；失败时给出温和反馈 |

#### 6.7.3 规则与边界

- 本地优先保存是默认策略，登录不是使用前置条件。
- 云端同步失败不能影响用户本地记录。
- 账号安全操作必须使用确认弹窗或明确提示，不使用系统 alert。
- 删除账户属于高风险操作，必须二次确认。

## 7. 支撑能力需求

### 7.1 数据保存与云端同步

| --- | --- |
| 本地保存 | 使用本地存储保存手记、日运、牌义注疏、小考记忆等 |

### 7.2 AI 辅助

| 能力 | 说明 |

| 牌名识别辅助 | 在用户输入不完整时尝试识别牌名 |

AI 辅助只承担整理和提示词生成，不替代用户自己的判断。涉及写入个人牌库的内容，需由用户确认后保存。

## 9. 非功能需求

### 9.1 移动端体验

- 以手机端使用为优先。
- 所有主要按钮触控面积不低于 44px。
- 输入框聚焦时需避免被键盘遮挡。
- 弹窗内容较多时必须可滚动。
- 危险操作在移动端默认隐藏在确认或多选之后。

### 9.2 可用性

- 核心记录流程不得强制登录。
- 本地保存失败、云端同步失败、导出失败都需要有可理解提示。
- 所有错误提示使用 Snackbar / Modal，不使用 `window.alert`。
- 用户正在编辑的内容不得因切换页面或网络失败直接丢失。

### 9.3 性能

- 初始页面优先加载首页核心内容。
- 低频页面使用懒加载，减少首屏负担。
- 牌面图片需要预加载或使用现代图片格式，减少闪烁。
- 长列表使用渐进展示，避免一次性渲染过多卡片。

### 9.4 安全与隐私

- 用户私有手记默认不公开。
- 公开分享必须由用户主动操作。
- 匿名公开时不展示用户昵称。
- 埋点不上传正文、标签、客户姓名、问题内容等隐私字段。
- 删除账户、删除记录、删除牌阵必须有确认机制。

### 9.5 视觉与品牌

- 保持森林感和手札感，使用 `forest-*` 调色体系。
- 标题使用 `font-serif` 和加粗，正文使用 `font-sans`。
- 动效使用 `motion/react`，保留轻量入场和弹窗过渡。
- 避免厚重卡片和过多嵌套卡片。
- 产品文案保持温柔、短句、低压力，不使用娱乐化算命口吻。

## 11. 风险与待确认

| 风险 / 问题 | 当前建议 | 状态 |
